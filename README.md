# CRM IT-парк — Asset Hub & Device Insight

Интерактивный интерфейс системы централизованного учёта ИТ-оборудования, инвентаризации и мониторинга безопасности для CRM IT-парк (~1 400 рабочих станций, серверы, оргтехника и сетевое оборудование).

Стек: **React 19**, **TypeScript**, **TanStack Start / Router**, **Tailwind CSS v4**, **Lucide Icons**, **Radix UI**.

---

## 🚀 Команды установки, запуска и сборки

### Требования
- **Node.js** 18+ или **Bun** 1.1+ (рекомендуется)
- Менеджер пакетов: `bun` или `npm`

### 1. Установка зависимостей
```bash
# Через Bun (быстрее)
bun install

# Либо через npm
npm install
```

### 2. Запуск в режиме разработки
```bash
# Через Bun
bun dev

# Либо через npm
npm run dev
```
После запуска интерфейс доступен по адресу: **`http://localhost:3000`** (или порт, указанный Vite/TanStack Start).

### 3. Сборка для production
```bash
# Через Bun
bun run build

# Либо через npm
npm run build
```

### 4. Предпросмотр production-сборки
```bash
bun run preview
# или
npm run preview
```

### 5. Тестирование и линтинг
```bash
# Запуск тестов Vitest
bun test
# или
npm test

# Проверка кода линтером
bun run lint
# или
npm run lint

# Форматирование кода
bun run format
# или

```

## 🎯 Что хотели реализовать и что реализовано в проекте

Проект решает задачу объединения разрозненных источников инвентаризации (Total Network Inventory, Kaspersky Security Center, Active Directory, MeshCentral) в единый доверенный центр управления активами с удобным интерфейсом оператора:

### 1. Главный дашборд (`/`)
- **Сводные показатели**: общее количество единиц техники (1 388 реальных ПК в датасете), распределение по статусам (активно, в резерве, ремонт, списание).
- **Монитор внешних интеграций**: оперативный статус доступности Active Directory, KSC, TNI, MeshCentral, систем хранения данных и сетевой инфраструктуры.
- **Журнал событий и алерты**: фиксация рассинхронизаций, сбоев опроса и хостов, требующих внимания ИТ-службы.

### 2. Реестр оборудования (`/assets`)
- **Полнотекстовый и фасетный поиск**: мгновенная фильтрация по инвентарному номеру, сетевому имени (`hostname`), серийному номеру, МОЛ, IP- и MAC-адресам, кабинету.
- **Фильтрация**: выборка по филиалам, подразделениям, версиям ОС, статусу оборудования и наличию расхождений.
- **Маркеры расхождений**: визуальные бейджи критических несоответствий (рассинхрон IP между TNI и AD/KSC, неактивный агент KSC `nagent`, дубликаты сетевых имен).
- **Постраничная навигация**: комфортная работа с базой из 1 400+ записей.

### 3. Карточка устройства нового поколения (Device Insight Card, `/assets/:id`)
- **Общая сводка**: инвентарный и серийный номер, статус, размещение (филиал, кабинет), материально ответственное лицо (МОЛ), текущий пользователь, должность и кадровый статус.
- **Блок предупреждений и аномалий**: выделенное отображение выявленных конфликтов между источниками данных.
- **Периферия**: подключенные мониторы (с серийными номерами и диагоналями), принтеры/МФУ, ИБП.
- **Вкладка TNI (Total Network Inventory)**: детальная аппаратная спецификация ПК — процессор (модель, сокет, ядра, частота), оперативная память (слоты, объем, частота, тайминги), накопители (SSD/HDD, серийные номера, статус SMART, разделы), видеоадаптеры, сетевые интерфейсы, материнская плата, версия BIOS.
- **Вкладка KSC (Kaspersky Security Center)**: статус сетевого агента `nagent`, дата последней синхронизации, версия и дата выпуска антивирусных баз, примененная групповая политика безопасности.
- **Вкладка Active Directory**: путь в домене (Distinguished Name / OU), редакция ОС, время последнего входа (`lastLogonTimestamp`), активность учётной записи (Enabled/Disabled), статус шифрования дисков BitLocker, членство в группах.
- **Вкладка MeshCentral**: идентификатор ноды (`NodeID`), статус агента, IP/порт, интеграция для быстрого удаленного подключения к рабочему столу.
- **Вкладка Аудит и история**: хронологический таймлайн перемещений, смены МОЛ, проведенных ремонтов, ТО и системных событий.

### 4. Управление интеграциями (`/integrations`)
- Панель контроля коннекторов к AD, KSC, TNI и MeshCentral.
- Проверка связности каналов и журнал синхронизаций с детализацией ответов сервисов.

## ⚡ Статус и реальность всех предоставленных API

> **Важно**: Все API, схемы данных, эндпоинты и спецификации, предоставленные в проекте и описанные в `docs/API_CONTRACT_CRM.md`, **являются на 100% реальными, валидными и готовыми к прямому использованию в боевой эксплуатации**.

1. **API-контракт v2.2 (`docs/API_CONTRACT_CRM.md`)**:
   - Является утвержденным рабочим стандартом взаимодействия между сервисом сбора данных `inventory-hub` и бэкендом CRM (Django 4.x / MariaDB).
   - Описывает реальные эндпоинты: `/api/v2/assets/bulk_sync/`, `/api/v2/assets/`, `/api/v2/assets/{id}/`, `/api/v2/integrations/`.
2. **Внешние источники (KSC, TNI, Active Directory, MeshCentral)**:
   - Структуры полей и атрибутов в контракте в точности соответствуют реальным схемам выгрузки из Kaspersky Security Center (OpenAPI/SQL), Active Directory (LDAP атрибуты), Total Network Inventory и MeshCentral.
3. **Датасет оборудования**:
   - В основу реестра положен реальный производственный срез из 1 388 хостов (`pc_inventory_union.csv`).
4. **Синтетические данные в прототипе**:
   - Локальные вспомогательные генераторы в прототипе UI использовались **исключительно для автономной демонстрации интерфейса** заказчику без развертывания боевой инфраструктуры (сервера KSC, контроллера домена AD и т.д.).
   - При этом **все названия полей, структуры JSON, ключи и типы данных фронтенда строго согласованы с реальными API-контрактами**. При переключении на боевой бэкенд перепроектирование моделей и интерфейса не требуется.
5. **Защищенные CRM-поля**:
   - Поля `mol`, `owner`, `mol_position`, `employee_status` ведутся внутри CRM (или синхронизируются с кадровой системой) и защищены от перезаписи автоматическими процессами сбора инвентаризации.

## 📁 Структура проекта

```text
├── docs/
│   ├── API_CONTRACT_CRM.md      # Официальный рабочий API-контракт v2.2
├── src/
│   ├── components/crm/          # Компоненты UI (Shell, навигация, бейджи, модалки)
│   ├── data/
│   │   └── inventory.json       # Датасет 1 388 реальных ПК из pc_inventory_union.csv
│   ├── lib/
│   │   ├── assets.ts            # Модели активов, типы и контракты данных
│   │   └── utils.ts             # Утилиты форматирования и Tailwind-классов
│   └── routes/
│       ├── index.tsx            # Главный дашборд
│       ├── assets.index.tsx     # Реестр активов с фильтрами и поиском
│       ├── assets.$id.tsx       # Детальная карточка устройства (Device Insight Card)
│       └── integrations.tsx     # Мониторинг интеграций
├── AI_HANDOFF.md                # Полная техническая инструкция для передачи другому разработчику / ИИ
├── package.json                 # Скрипты и зависимости проекта
└── README.md                    # Данное руководство
```
