# CRM IT-парк — Asset Hub, Device Insight & Antivirus Hub

Интерактивный интерфейс системы централизованного учёта ИТ-оборудования, инвентаризации, антивирусного мониторинга и информационной безопасности для CRM IT-парк (~1 400 рабочих станций, серверы, оргтехника и сетевое оборудование).

Стек: **React 19**, **TypeScript**, **TanStack Start / Router**, **Tailwind CSS v4**, **Lucide Icons**, **Radix UI** (автономный чистый SPA-клиент, без серверных ORM и лишних зависимостей).

### Требования

- **Node.js** 18+ или **Bun** 1.1+ (рекомендуется)
- Менеджер пакетов: `bun` или `npm`

```bash
# Через Bun (быстрее)
bun install

# Либо через npm
npm install
```

```bash

# Либо через npm
npm run dev
```

## 🛡️ Модуль «Антивирус» (Доработка вкладки и AI-сопоставления)

В систему заложен и реализован специализированный модуль антивирусного мониторинга:

1. **Вкладка «Антивирус» в карточке устройства (`/assets/:id`)**:
   - Расширяет базовый KSC: разделяет подтверждённую установку агента администрирования (`agentInstallation`) и сетевую доступность/видимость (`agentAvailability`).
   - Отображает данные **Kaspersky Security Center (KSC)**: статус сетевого агента `nagent`, даты синхронизации, версию KES, актуальность баз и групповые политики.
   - Детектирует **стороннее антивирусное ПО**: из списка установленных программ (TNI) выделяются другие антивирусы с отображением источника и даты обновления.
   - Блок антивирусного статуса вынесен в общую сводку устройства (`Summary`).
2. **Автономный справочник и сопоставление антивирусов и СЗИ (100% бесплатно, без подписок и сети)**:
   - Модуль `LocalSecurityMatcher.tsx` (`src/lib/security-catalog.ts`, страница `/security-catalog`).
   - Встроенная база сигнатур 30 антивирусов и российских/международных СЗИ (Лаборатория Касперского, Dr.Web, ESET, Defender, Код Безопасности Secret Net/Континент/Соболь, ИнфоТеКС ViPNet, КриптоПро, Dallas Lock, InfoWatch, СёрчИнформ, DeviceLock, Zecurion и др.).
   - Автономный поиск и классификация без интернета, без серверных функций, без платных токенов и подписок к языковым моделям.
   - Предотвращает выдумывание версий и галлюцинации нейросетей, гарантирует мгновенный детерминированный результат.
3. **Фильтрация и экспорт в реестре (`/assets`)**:
   - Фильтры по наличию антивируса и статусу актуальности баз.
   - Экспорт в CSV с 4 специализированными антивирусными колонками (`src/lib/inventory-csv.ts`).
4. **Тесты и схема данных**:
   - Автотесты: `antivirus.test.ts`, `ksc-agent.test.ts`, `security-catalog.test.ts` (140 тестов сигнатур), `app-routing.test.tsx`.
   - Чек-лист реализации: `roadmap.md`.

## 🎯 Что реализовано в проекте (Цели и возможности)

### 1. Главный дашборд (`/`)

- **Сводные показатели**: общее количество единиц техники (1 388 реальных ПК в датасете), распределение по статусам (активно, в резерве, ремонт, списание).
- **Монитор внешних интеграций**: оперативный статус доступности Active Directory, KSC, TNI, MeshCentral, систем хранения данных и сетевой инфраструктуры.
- **Журнал событий и алерты**: фиксация рассинхронизаций, сбоев опроса и хостов, требующих внимания ИТ-службы.

### 2. Реестр оборудования (`/assets`)

- **Полнотекстовый и фасетный поиск**: фильтрация по инвентарному номеру, сетевому имени (`hostname`), серийному номеру, МОЛ, IP- и MAC-адресам, кабинету.
- **Фильтрация**: выборка по филиалам, подразделениям, версиям ОС, статусу оборудования, наличию расхождений и антивирусному статусу.
- **Маркеры расхождений**: визуальные бейджи критических несоответствий (рассинхрон IP между TNI и AD/KSC, неактивный агент KSC `nagent`, дубликаты сетевых имен).
- **Постраничная навигация и экспорт**: комфортная работа с базой из 1 400+ записей и выгрузка в CSV.

### 3. Карточка устройства (Device Insight Card, `/assets/:id`)

- **Общая сводка**: инвентарный и серийный номер, статус, размещение, МОЛ, текущий пользователь, кадровый статус и плашка антивирусного статуса.
- **Блок предупреждений и аномалий**: выделенное отображение выявленных конфликтов между источниками данных.
- **Периферия**: подключенные мониторы (с серийными номерами и диагоналями), принтеры/МФУ, ИБП.
- **Вкладка TNI (Total Network Inventory)**: детальная аппаратная спецификация (процессор, ОЗУ, SSD/HDD со SMART, видеоадаптеры, сетевые интерфейсы, материнская плата, BIOS).
- **Вкладка «Антивирус»**: детальный статус KSC + сторонние антивирусы + AI-анализ программного обеспечения.
- **Вкладка Active Directory**: путь в домене (Distinguished Name / OU), редакция ОС, время последнего входа (`lastLogonTimestamp`), активность учётной записи (Enabled/Disabled), статус BitLocker.
- **Вкладка MeshCentral**: идентификатор ноды (`NodeID`), статус агента, IP/порт, быстрый запуск сеанса удаленного доступа.
- **Вкладка История и аудит**: хронологический таймлайн перемещений, смены МОЛ, проведенных ремонтов и событий.

### 4. Управление интеграциями (`/integrations`)

- Панель контроля коннекторов к AD, KSC, TNI и MeshCentral, проверка связности и журнал обращений к API.

> **Важно**: Все API, схемы данных, эндпоинты и спецификации, предоставленные в проекте и описанные в `docs/API_CONTRACT_CRM.md`, **являются на 100% реальными, валидными и готовыми к прямому использованию в боевой эксплуатации**.

1. **API-контракт v2.2 (`docs/API_CONTRACT_CRM.md`)**:
   - Является утвержденным рабочим стандартом взаимодействия между сервисом сбора данных `inventory-hub` и бэкендом CRM (Django 4.x / MariaDB).
   - Описывает реальные эндпоинты: `/api/v2/assets/bulk_sync/`, `/api/v2/assets/`, `/api/v2/assets/{id}/`, `/api/v2/integrations/`.
2. **Внешние источники (KSC, TNI, Active Directory, MeshCentral)**:
   - Структуры полей и атрибутов в контракте в точности соответствуют реальным схемам выгрузки из Kaspersky Security Center (OpenAPI/SQL), Active Directory (LDAP атрибуты), Total Network Inventory и MeshCentral.
3. **Датасет оборудования**:
   - В основу реестра положен реальный производственный срез из 1 388 хостов (`pc_inventory_union.csv`).
4. **Синтетические данные в прототипе**:

5. **Защищенные CRM-поля**:
   - Поля `mol`, `owner`, `mol_position`, `employee_status` ведутся внутри CRM и защищены от перезаписи при автоматической синхронизации.

## ⚠️ Коллизии, противоречия и архитектурные нюансы

1. **Отставание ветки `feature/integration-config-form` от `main`**:
   - Ветка ответвилась до удаления AntivirusAi и Drizzle ORM. При возобновлении работ над формой потребуется выполнить `git rebase main` (или чистый merge), чтобы не вернуть удалённый мёртвый код.
2. **Разделение зон ответственности источников данных (Single Source of Truth)**:
   - **Аппаратные данные (CPU, RAM, диски, мониторы)**: источником правды является **Total Network Inventory (TNI)**.
   - **Доменные атрибуты (OU, статус учётной записи, BitLocker, lastLogon)**: источником правды является **Active Directory (AD)**.
   - **Антивирусная защита и базы**: источником правды является **Kaspersky Security Center (KSC)**.
   - **Удалённое управление**: источником правды является **MeshCentral**.
   - **Учётные и кадровые поля (МОЛ, пользователь, статус)**: источником правды является **CRM IT-парк** (ручной ввод оператора или синхронизация с 1С:ЗУП). Сканеры железа не имеют права их перезаписывать.
3. **Папка `supabase/` в проекте**:
   - Является начальным конфигурационным артефактом Lovable. В кодовой базе React/Vite прямых зависимостей от Supabase больше нет (Drizzle ORM и вызовы SDK удалены). Папку можно игнорировать или безопасно удалить при переносе в автономный контур.

## 🔌 Используемые API и межсистемное взаимодействие (Получение данных с других проектов и систем)

### Схема потоков данных:
`Внешние системы (AD, KSC, TNI, MeshCentral, 1C)`  
⬇ *(фоновый опрос / скрипты сборщика)*  
`Сервис сбора данных inventory-hub`  
⬇ *(пакетная синхронизация POST /api/v2/assets/bulk_sync/)*  
`Django CRM Backend (crm-app:8000 / MariaDB)`  
⬇ *(REST API v2 с поддержкой прав доступа perm_set)*  
`Frontend (React SPA / Django Templates)`

### 1. API взаимодействия с бэкендом CRM (Django REST Framework v2)

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/api/v2/assets/` | Получение реестра активов с поддержкой фильтрации (по статусу, антивирусу, подразделению), полнотекстового поиска и пагинации. |
| `GET` | `/api/v2/assets/{id}/` | Полная карточка устройства со всеми связанными объектами (TNI-спецификация, KSC-статус, AD-атрибуты, мониторы, история). |
| `PATCH` | `/api/v2/assets/{id}/` | Частичное обновление карточки: изменение МОЛ, пользователя, кабинета, статуса списания/ремонта, привязка мониторов/принтеров. |
| `POST` | `/api/v2/assets/bulk_sync/` | Приём пакетного снимка оборудования от сервиса `inventory-hub` (API-контракт v2.2). |
| `GET` | `/api/v2/assets/sync_status/` | Проверка времени и результата последней автоматической синхронизации. |
| `POST` | `/api/v2/assets/export_csv/` | Формирование серверного CSV-файла инвентаризации с 4 антивирусными колонками. |
| `POST` | `/api/v2/login/` / `/api/v2/logout/` | Сессионная аутентификация в CRM (поддержка CSRF, роли `view`, `create`, `edit`, `delete`, `audit`). |
| `GET` | `/api/v2/me/` | Получение профиля текущего пользователя и его прав доступа (`perm_set`). |
| `GET` | `/api/v2/integrations/` | Получение перечня настроенных внешних коннекторов (без раскрытия секретов). |
| `POST` | `/api/v2/integrations/test/` | Проверка сетевой связности с KSC, AD, TNI, MeshCentral, 1С. |

### 2. Внешние протоколы и API источников данных (как данные собираются из сторонних проектов)

1. **Kaspersky Security Center (KSC)**:
   - **Протокол**: KSC OpenAPI (REST HTTPS, порт 13292) / прямой SQL-доступ к БД KSC.
   - **Эндпоинты KSC OpenAPI**:
     - `POST https://ksc-server:13292/api/v1.0/login` — авторизация сервисной учётной записи.
     - `POST https://ksc-server:13292/api/v1.0/HostGroup.FindHosts` — выборка зарегистрированных хостов по группам администрирования.
     - `POST https://ksc-server:13292/api/v1.0/HostGroup.GetHostInfo` — получение состояния сетевого агента `nagent`, даты баз, версии антивируса KES и активных политик.
2. **Active Directory (AD / DC)**:
   - **Протокол**: LDAP / LDAPS (TCP 389 / 636).
   - **Метод**: подключение по сервисной учетной записи через `python-ldap` / `ldap3`.
   - **Фильтр поиска**: `(&(objectCategory=computer)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))`.
   - **Атрибуты**: `sAMAccountName`, `dNSHostName`, `distinguishedName` (OU путь), `operatingSystem`, `operatingSystemVersion`, `lastLogonTimestamp`, `whenCreated`, `msTPM-OwnerInformation`, статус BitLocker.
3. **Total Network Inventory (TNI)**:
   - **Протокол**: Прямое чтение файла базы данных хранилища SQLite `inventory.tni` либо плановый CLI-экспорт отчётов сканирования в формате XML/CSV.
   - **Извлекаемые сущности**: подробный перечень оборудования (CPU, слоты и планки RAM с таймингами, накопители с атрибутами SMART, видеокарты, сетевые интерфейсы, серийные номера и EDID мониторов, установленное ПО).
4. **MeshCentral**:
   - **Протокол**: MeshCentral REST API & WebSocket (порт 443).
   - **Авторизация**: заголовок `x-token` (MeshCentral API Login Token).
   - **Эндпоинты**:
     - `GET /api/meshagents` — список активных агентов удалённого доступа и их внешние/внутренние IP-адреса.
     - `GET /api/meshdevices` — детальные параметры нод (`NodeID`, `mesh_group`).
     - `POST /api/meshcommand` — отправка управляющих команд администратора.
5. **1С:Предприятие (ЗУП / Бухгалтерия)**:
   - **Протокол**: 1C OData REST API (HTTP Basic Auth) либо HTTP-сервис обмена.
   - **Эндпоинты OData**:
     - `GET /odata/standard.odata/Catalog_Сотрудники?$select=Ref_Key,Description,Code,Подразделение,Должность` — сопоставление пользователей и МОЛ с кадровой базой.
     - `GET /odata/standard.odata/InformationRegister_КадроваяИсторияСотрудников` — получение статуса сотрудника (активен, уволен, в отпуске).
