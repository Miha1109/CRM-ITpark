# AI handoff: CRM IT-парк

## Что это
Прототип интерфейса учёта ИТ-оборудования для CRM IT-парк. React 19 + TypeScript, TanStack Start/Router, Tailwind CSS v4. Это фронтенд-прототип с локальными моковыми данными, а не подключённая к рабочему серверу CRM.

## Основные экраны
- `/` — дашборд с агрегатами и состоянием интеграций.
- `/assets` — реестр 1 388 записей ПК с поиском, фильтрами, флагом расхождений и постраничным выводом.
- `/assets/:id` — карточка ПК: сводка, CRM-поля, периферия, предупреждения и вкладки TNI/KSC/AD/MeshCentral/история.
- `/integrations` — макет страницы интеграций и журнала.

## Важные файлы
- `src/data/inventory.json` — 1 388 строк, импортированных из `pc_inventory_union.csv`.
- `src/lib/assets.ts` — типы и генерация моковых полей для UI.
- `src/routes/assets.index.tsx` — реестр.
- `src/routes/assets.$id.tsx` — карточка устройства.
- `src/routes/index.tsx`, `src/routes/integrations.tsx` — дашборд и интеграции.
- `src/components/crm/Shell.tsx` — навигация и общие компоненты.
- `docs/API_CONTRACT_CRM.md` — API-контракт из материалов пользователя.

## Для дальнейшей работы
1. Сначала сверяй изменения и payload с `docs/API_CONTRACT_CRM.md`; не меняй схему `assets[]` без согласования.
2. Большинство полей KSC/AD/Mesh, статусов, подразделений, МОЛ/владельцев, ПО и журнала сейчас синтетические примеры для интерфейса. Не считай их данными реальных источников.
3. Поля `mol`, `owner`, `mol_position`, `employee_status` — CRM-protected поля: при интеграции с `inventory-hub` не перезаписывать их автоматической синхронизацией.
4. Не показывай на фронтенде `FIELD_ENCRYPTION_KEY` или `secret_encrypted`; любые secrets должны храниться только на сервере.
5. Авторизацию/права строить по текущему Django backend и его `perm_set` (view/create/edit/delete), не добавлять фиктивную авторизацию в UI.
6. Для переноса в Django используй `django/core/templates/` и `django/static/`, подставляй серверные данные из существующих views/API, учитывай Django CSRF для POST/PATCH и скрывай действия по ролям.

## Запуск локально
```bash
bun install
bun dev
```
Либо `npm install && npm run dev`. Для сборки: `bun run build`.

## Ограничения этого прототипа
В проекте реальные CSV-данные используются для инвентаризационных полей. Генерируемые KSC/AD/Mesh/CRM значения нужны только для демонстрации вкладок. Кнопки и пункты интерфейса, не относящиеся к дашборду, реестру, карточке и интеграциям, могут быть недоступны. Перед реальным внедрением проверить зависимости, типы полей и API endpoint-ы против Django-контракта.
